# Архитектура решения

## Контекст

Офлайн-приложение для Android (Kotlin, XML-UI): распознавание русской речи
с диаризацией говорящих, пунктуацией и LLM-анализом (конспект, главы, склейка
разрезанных фраз). Вся обработка — на устройстве, сеть не используется ни на
одном этапе. Пайплайн — конвейер из пяти стадий с единым JSON-контрактом на выходе.

## Компоненты

Три слоя; обмен между UI и ML — только через каноничный JSON (docs/PROTOCOL.md):

1. **UI-слой** — `MainActivity`: один запуск полного пайплайна, живые прогрессбары
   и ETA по этапам, табы результата (Текст/Сводка/Главы), плеер с навигацией
   по таймкодам, экспорт. Оформления A/B/C (скины + анимации) — `Skin`.
2. **Состояние** — application-scoped (companion): переживает поворот экрана;
   стадии `Декод → ASR → Диаризация → Пунктуация → LLM-анализ` с реальным
   процентом на каждую стадию.
3. **Пайплайн (ML)** — `Pipeline.kt`, `PunctEngine.kt`, `LlmEngine.kt`,
   `AudioDecoder.kt`:
   - **Декод** — `MediaCodec`/`MediaExtractor`: wav/mp3/ogg/flac/m4a → моно 16 кГц;
   - **ASR** — sherpa-onnx `OfflineRecognizer`, GigaAM v3 RNN-T int8
     (`nemo_transducer`, 64 мел-бинов), чанки 60 с;
   - **Диаризация** — sherpa-onnx `OfflineSpeakerDiarization`: pyannote
     segmentation-3.0 → CAM++ эмбеддинги → FastClustering (threshold 0.7);
     ID спикеров глобальны на всю запись;
   - **Merge** — сопоставление реплик и спикеров по пересечению времени;
   - **Пунктуация** — RUPunct-small int8 (BERT token-classifier, WordPiece-токенизатор
     на Kotlin, ONNX Runtime): пунктуация + регистр за миллисекунды;
   - **LLM-анализ** — QVikhr-3-1.7B int4 (ONNX Runtime GenAI): склейка случайно
     разрезанных фраз → главы с таймкодами → конспект.

## Основные технические решения

- Движки: **sherpa-onnx 2.0.1** (AAR, ASR+диаризация), **ONNX Runtime 1.23.0 +
  GenAI 0.19.0** (LLM), **ONNX Runtime** (RUPunct). Все — локальные рантаймы
  из списка допустимых; NNAPI не используется (нестабилен в готовых AAR).
- ASR-модель по умолчанию — **GigaAM v3** (WER 0.121 против 0.147 у компактного
  zipformer; цена — 221 MiB против 25.7 MiB). Альтернатива зафиксирована в
  манифесте моделей.
- **Чанкинг 60 с** — родной режим GigaAM (лимит ~200 с, деградация >90 с);
  нарезки 19 с, необходимой zipformer, больше нет.
- **Глобальная диаризация** на всю запись (не по чанкам) — ID спикеров стабильны
  в отличие от початковых решений, где `speaker_1` в разных чанках — разные люди.
- **Пунктуация — отдельная крошечная модель (т9-класс)**, а не LLM: 2 мс/сегмент
  против секунд, F1 0.838 против 0.757, 28 MiB против 1.1 GiB. LLM освобождён
  для смысловых задач (конспект/главы/склейка).
- Склейка разрезанных фраз: LLM только предлагает пары строк, слияние выполняется
  детерминированным кодом (текст не переписывается).
- Экран письменно разбит на три состояния (источник → прогресс → результат);
  прогрессбары настоящие: ASR — по чанкам, диаризация — callback кадров sherpa,
  пунктуация — по сегментам; ETA пересчитывается по фактическому темпу стадии.

## Зависимости

- `sherpa-onnx.aar` v2.0.1, `onnxruntime-android` 1.23.0, `onnxruntime-genai-android` 0.19.0
  (в `app/libs`, AAR не в git — восстановление по MANIFEST);
- androidx не используется (минимальный платформенный UI);
- модели в assets приложения: GigaAM v3 (221 MiB), pyannote+CAM++ (34 MiB),
  RUPunct (28 MiB), QVikhr int4 (1.03 GiB), промпты;
- python-инструменты (`src/tools`) — для eval и исследований, в приложение не входят.

## Безопасность и приватность

- Полный офлайн: permission `INTERNET` в приложении отсутствует, сетевых вызовов
  в рантайме нет.
- Записи с микрофона — только в приватный `cacheDir`; экспорт — в приватный
  `filesDir` приложения.
- Код не содержит «зашитых» эталонных расшифровок — весь текст выводится моделью.
- Веса моделей имеют разрешающие лицензии (MIT/Apache-2.0); кандидаты с NC/
  отсутствующей лицензией отклонены на этапе ресерча (см. docs/RESEARCH.md).
